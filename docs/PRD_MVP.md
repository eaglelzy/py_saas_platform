# 企业级 SaaS 平台 MVP 需求文档

**版本:** 1.1  **日期:** 2025-XX-XX  
**范围:** 面向留学中介顾问（C 端）优先交付的 SaaS MVP，随后扩展到留学中介公司（B 端）

---

## 1. 产品概述
- **愿景**：以最小成本交付面向留学中介顾问（C 端）的申校工作台，先满足「客户管理 + 进度更新 + 基础提醒」等核心流程，验证收费模式与真实需求，再逐步扩展到留学中介公司（B 端）的机构管理能力。
- **用户角色**  
  - 顾问（Consultant，C 端）：独立或隶属于中介机构的申校顾问，使用系统管理客户与申请流程。  
  - 顾问主管 / 机构管理员（可选阶段）：在 B 端扩展时负责顾问授权、模板配置、数据审核。  
  - 平台运营（Platform Admin）：内部团队，负责顾问自助注册审核、订阅管理、运营支撑。  
- **核心假设**：  
  1. 大量顾问存在工具空缺，愿意尝试“免费 + 升级订阅”的 SaaS。  
  2. 顾问可自助在线注册，提交基础资料，由运营审核后开通；未来可接受机构邀请。  
  3. 免费版通过客户数量 / 学校数量 / 存储空间等限制控制成本；付费版以提升效率的高级功能吸引转化。

---

## 2. 技术选型（MVP 保留项）
- **后端**：Python 3.12 + FastAPI + SQLAlchemy。
- **数据库**：PostgreSQL（单实例，按 `tenant_id` 建立 RLS；预留按租户迁移子库能力）。  
- **缓存**：Redis（JWT 黑名单、限流、短期缓存）。  
- **队列**：RabbitMQ（异步发送通知、订阅事件，可在 MVP 中占位但只处理关键消息）。  
- **前端**：Angular 20 + TypeScript + Angular CLI（租户控制台 + 平台运营台，Standalone 组件架构）。  
- **部署**：Docker Compose；GitHub Actions（Lint + Test + Build）。  
- **日志/监控**：Loguru（开发彩色日志） + 结构化 JSON 日志；`/health` 与 `/readiness`；Prometheus + Grafana 模板（CPU、内存、HTTP 指标、队列堆积）。

---

## 3. 功能需求（MVP 范围）——聚焦 C 端顾问
### 3.1 顾问账号与身份管理
1. **在线注册**：顾问填写姓名、公司（可选）、邮箱/手机号、服务国家、工作年限，并在注册表单中直接设置登录密码；提交前需完成验证码（图形或短信）校验，防止批量脚本注册；提交后即创建可登录账号。  
2. **审核流程（预留）**：系统可记录“待审核”状态供后期运营人工复核，目前默认自动通过；运行日志中保留审核占位逻辑，后续可开启强制审批。  
3. **登录与安全**：邮箱 + 密码登录，密码规则 ≥8 位且包含大小写/数字；支持重置密码、登出、刷新 Token。  
4. **顾问档案**：顾问可以维护个人简介、擅长项目、服务标签，为后续匹配服务做准备。

### 3.2 客户与申请管理（免费版核心）
1. **客户管理**：创建/编辑/归档客户（学生）资料，包含基本信息、意向国家、目标院校、当前状态。  
2. **申请进度**：为每位客户维护申请阶段（规划 → 选校 → 文书 → 递交 → 审核 → 录取/签证）及预计时间节点；支持进度更新记录时间线。  
3. **基础提醒**：顾问可创建手动提醒（时间 + 内容），系统在提醒日前 1 天弹出站内通知/邮件提示。  
4. **存储限制**：免费版最多管理 N 个客户（建议 20）与 M 所目标院校（建议 10），文件存储限 200MB。

### 3.3 付费版高级功能
1. **材料模板库**：提供 SOP/推荐信/简历模板，可自定义保存模板。  
2. **自动提醒**：系统根据申请阶段的计划时间自动生成提醒（如文书截止、签证预约），支持多次提醒策略。  
3. **统计报表**：按阶段统计客户数量、转化率、签约金额（若录入）、应用渠道；提供周报/月报。  
4. **云存储扩展**：提升存储空间（如 5GB），支持文件夹管理、快速预览、版本记录。  
5. **半自动化申校**：集成院校库或第三方 API，自动生成选校清单、导出材料 Checklist。

### 3.4 认证与授权（顾问视角）
1. JWT（Access 1 小时、Refresh 7 天），Redis 黑名单支持强制登出。  
2. 顾问默认只访问个人客户数据；未来扩展 B 端时通过 `tenant_id` 限制数据范围。  
3. 审核通过的顾问标记为 `active`，未通过或违规的顾问可设置 `suspended` 并拒绝登录。

### 3.5 订阅与收费
1. **版本策略**：  
   - 免费版：核心功能（客户管理、进度更新、基础提醒），限制客户/院校/存储。  
   - 订阅版（按月/年）：解锁高级功能（模板、自动提醒、报表、扩展存储、半自动申校等）；支持试用期。  
2. **计费与续费**：顾问可在“账户设置”查看当前版本、升级计划、支付记录；使用 Stripe/国内支付渠道或暂时人工确认。  
3. **到期/欠费处理**：到期前 7 天/1 天发送提醒，逾期 7 天自动降级为免费版并保留数据但限制操作。

### 3.6 平台运营支撑
1. 顾问申请审核列表、详情、通过/驳回操作，记录审核日志。  
2. 顾问订阅管理：查看当前订阅、支付记录、手动调整套餐（仅运营可用）。  
3. 顾问反馈与支持：简单工单或意见箱，占位后续客服系统。  
4. 保留扩展至 B 端所需的租户管理、成员邀请、报表等模块，但在 C 端 MVP 中可隐藏/降级。

## 4. 非功能需求（MVP）
- **性能目标**：单节点支持 200 并发请求，P95 < 400ms；API 调用配额以 Redis 计数。  
- **安全基线**：  
  - 全量 HTTPS；敏感数据（密码、Token）按 PBKDF2 + JWT；  
  - 输入校验、SQL 注入/XSS 防护；  
  - 管理端操作需二次确认；  
  - 日志包含 `tenant_id`、`user_id`。  
- **可用性**：服务异常时返回统一错误格式；RabbitMQ/Redis 不可用时降级为同步操作并记录告警。  
- **备份**：每日数据库备份（逻辑备份即可），手动触发恢复脚本；日志保留 30 天。

## 5. 迭代路线图
1. **Sprint 1（第 1–2 周）**：  
   - 顾问注册/审批/登录、基础客户管理、申请阶段模型与手动提醒。  
   - 前端顾问工作台主体、客户列表/详情、提醒面板；后端审计日志、JWT。  
2. **Sprint 2（第 3–4 周）**：  
   - 订阅与收费骨架（免费/专业版配置、升级流程、简单支付确认）。  
   - 自动提醒逻辑、材料模板存储（占位）、文件上传与空间限制。  
   - Prometheus/Grafana/日志完善、CI/CD、Docker Compose。  
3. **Sprint 3（第 5–6 周）**：  
   - 报表与统计原型、半自动化申校（院校模板/Checklist）、性能调优。  
   - 顾问反馈收集、试用邀请码、上线 Checklist，准备首批顾问试运营。  
4. **B 端扩展路线（后续）**：机构租户入驻 → 机构管理员邀请顾问 → 机构级报表 → 多租户运营台 → 线上支付/自动扣费 → 更复杂的 RBAC、自定义模板库 → Webhook/第三方集成。

---

## 6. 交付物与验收
- FastAPI 应用（`/api/v1`），Angular 顾问工作台 + 运营后台，Docker Compose 本地环境。  
- 单元/集成测试覆盖核心流程（≥60%）；文档：顾问使用指南、运营审核手册、部署运维清单。  
- 首批 30 位顾问完成注册试用，其中 ≥5 位转化为订阅付费；收集反馈用于后续 B 端扩展规划。
