# 企业级 SaaS 平台 MVP 需求文档

**版本:** 1.0  **日期:** 2025-XX-XX  
**范围:** 面向中小企业客户的多租户 SaaS 基础平台（单人研发阶段）

---

## 1. 产品概述
- **愿景**：以最小成本构建面向中小企业的账号与订阅管理平台，先满足“租户管理 + 权限控制 + 订阅升级”三大核心需求，快速上线验证市场，再按反馈迭代。
- **用户角色**  
  - 平台管理员（Platform Admin）：内部运营、审核租户、确认支付、配置套餐。  
  - 企业管理员（Tenant Owner）：发起入驻、管理成员、提交订阅或升级申请。  
  - 企业成员（Tenant Member）：被邀请加入租户，访问业务功能。  
- **核心假设**：中小客户可接受线下审核与支付流程，先提供固定套餐，后续再扩展自动计费、自定义权限等高级能力。

---

## 2. 技术选型（MVP 保留项）
- **后端**：Python 3.12 + FastAPI + SQLAlchemy。
- **数据库**：PostgreSQL（单实例，按 `tenant_id` 建立 RLS；预留按租户迁移子库能力）。  
- **缓存**：Redis（JWT 黑名单、限流、短期缓存）。  
- **队列**：RabbitMQ（异步发送通知、订阅事件，可在 MVP 中占位但只处理关键消息）。  
- **前端**：Vue 3 + TypeScript + Vite（租户后台 + 平台运营台）。  
- **部署**：Docker Compose；GitHub Actions（Lint + Test + Build）。  
- **日志/监控**：Loguru（开发彩色日志） + 结构化 JSON 日志；`/health` 与 `/readiness`；Prometheus + Grafana 模板（CPU、内存、HTTP 指标、队列堆积）。

---

## 3. 功能需求（MVP 范围）
### 3.1 租户与成员管理
1. 企业管理员注册 → 提交企业信息（名称、联系人、邮箱/手机号） → 平台管理员审核通过即创建租户。  
2. 固定 3 个角色：`owner`（创建者，拥有全部权限）、`admin`（可管理成员及订阅）、`member`（仅业务访问）。  
3. 成员邀请：管理员输入邮箱发送邀请链接；成员接受后激活账号。  
4. 成员上限由套餐控制（免费 5 人、专业 30 人）；超限时禁止新增并提示升级。

### 3.2 认证与授权
1. 邮箱 + 密码登录；密码须满足最少 8 位且包含字母与数字。  
2. JWT（Access 1 小时、Refresh 7 天），Redis 维护黑名单；支持手动登出。  
3. 用户可加入多个租户，登录后选择当前租户；JWT 中写入 `tenant_id` 并在 DB Session 中执行 `SET app.current_tenant`。  
4. RBAC 校验：后端根据角色与预置权限表判定访问；权限缓存 15 分钟。

### 3.3 订阅与升级
1. 预置两个套餐：  
   - 免费版：1 名成员、API 调用 1 万次/月。  
   - 专业版：10 名成员、API 调用 5 万次/月、优先支持。  
2. 企业管理员可在后台提交“升级申请”，填写联系人及备注。  
3. 平台管理员在线下确认收款后，在运营台手动标记订单为“已支付”，系统立即将租户套餐切换为专业版。  
4. 到期提醒：到期前 7 天、1 天发送邮件 + 站内通知；逾期 7 天后自动降级为免费版并记录日志。

### 3.4 审计与通知
1. 关键事件审计：登录、成员增删、角色变更、套餐变更、支付确认。  
2. 审计数据写入 PostgreSQL；支持按时间和租户过滤。  
3. 通知方式：站内消息 + 邮件（SMTP），RabbitMQ 触发异步发送；失败记录到审计日志。

### 3.5 平台运营台
1. 查看租户列表、状态、当前套餐、到期时间、成员数。  
2. 审核入驻申请、重置租户状态、标记支付、发站内通知。  
3. 查看订阅订单、导出 CSV 报表（线下对账用）。

---

## 4. 非功能需求（MVP）
- **性能目标**：单节点支持 200 并发请求，P95 < 400ms；API 调用配额以 Redis 计数。  
- **安全基线**：  
  - 全量 HTTPS；敏感数据（密码、Token）按 PBKDF2 + JWT；  
  - 输入校验、SQL 注入/XSS 防护；  
  - 管理端操作需二次确认；  
  - 日志包含 `tenant_id`、`user_id`。  
- **可用性**：服务异常时返回统一错误格式；RabbitMQ/Redis 不可用时降级为同步操作并记录告警。  
- **备份**：每日数据库备份（逻辑备份即可），手动触发恢复脚本；日志保留 30 天。

---

## 5. 迭代路线图
1. **Sprint 1（第 1–2 周）**：  
   - 完成租户入驻流、成员邀请、基础 RBAC、中后台页面骨架。  
   - 实现 JWT + Redis 黑名单、RLS、审计日志。  
2. **Sprint 2（第 3–4 周）**：  
   - 套餐配置、升级申请、线下支付确认、到期提醒、站内通知。  
   - GitHub Actions、Docker Compose 脚本、基础监控/日志。  
3. **Sprint 3（第 5–6 周）**：  
   - RabbitMQ 异步通知、导出报表、限流与配额统计、基础性能优化。  
   - 撰写用户指南、上线 checklist、收集早期客户反馈。  
4. **后续优先级**：在线支付 → 自定义角色 → Webhook/集成 → 自动计费 → 高级监控/告警 → SSO。

---

## 6. 交付物与验收
- FastAPI 应用（`/api/v1`），Vue 管理端（运营台 + 租户端），Docker Compose 本地环境。  
- 单元/集成测试覆盖核心流程（≥60%）；文档：部署指南、API 手册、运维清单。  
- 首批 3–5 家中小企业完成试运行并支付升级费用，形成反馈循环。
